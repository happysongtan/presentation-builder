Backend Stabilization

안정화는 “문제 없는 코드”가 아니라 “예측 가능한 서비스”를 만드는 일입니다.

현재 프로젝트의 인증, 거래 기록, 통계/결산, 농장 API를 기준으로 안정화 정의·판정 기준·실행 로드맵을 정리했습니다.

Dondoc V2 Backend2026.06.30
Definition

안정화란 기능을 더 붙이는 단계가 아니라, 이미 만든 기능이 반복 실행되어도 같은 품질로 동작하게 고정하는 단계입니다.

Correctness

정확성

수입·지출 합계, 월별 결산, 카테고리 집계, 사용자 예산 계산이 요구사항과 API 문서대로 재현되어야 합니다.

Reliability

신뢰성

잘못된 입력, 없는 사용자, 권한 없는 거래 접근, DB 제약 위반에도 서버가 일관된 오류 응답을 반환해야 합니다.

Operability

운영 가능성

빌드, 테스트, 로그, 설정, 배포 전 점검이 반복 가능한 절차로 남아야 다음 변경도 안전하게 흡수할 수 있습니다.

오류

400/401/403/404/409/500 응답 일관성

점검해야 할 코드 영역

  • AuthService: 회원가입 중복, 로그인 실패, 비밀번호 처리 기준
  • RecordService: 거래 CRUD, 월별 조회, 통계·결산 계산
  • FarmService: 농장 생성·가입·탈퇴와 멤버 권한
  • GlobalExceptionHandler: 공통 응답 메시지와 HTTP 상태 코드
  • application.yaml: DB 비밀번호, local profile, SQL 로그 노출
리스크 우선순위05 / 10
Process

돈독 백엔드 안정화는 5단계로 진행하면 범위를 잃지 않고 품질을 올릴 수 있습니다.

1. 기준선 고정
  • 현재 빌드 결과 확인
  • API 목록 확정
  • 알려진 이슈 수집
2. 계약 정리
  • 상태 코드 통일
  • 응답 포맷 통일
  • 문서 인코딩 복구
3. 핵심 테스트
  • 서비스 단위 테스트
  • 컨트롤러 테스트
  • 통계 계산 케이스
4. 운영 점검
  • 환경변수 분리
  • 로그 레벨 조정
  • CORS와 DB 설정 검증
5. 회귀 방지
  • CI 품질 게이트
  • 릴리즈 체크리스트
  • 장애 회고 템플릿

P1 월별 요약·일별 요약·결산 계산 테스트 추가 경계값, 빈 데이터, 수입만/지출만 케이스 통과
P1 API 문서와 실제 컨트롤러 응답 정렬 프론트엔드가 문서만 보고 연동해도 실패하지 않음
P2 로그와 예외 메시지 정리 장애 원인은 추적 가능하지만 민감 정보는 노출되지 않음
